## 1. 目标

二次开发者**不写后端代码**：在管理界面定义业务对象（如"设备台账"）→ 发布 → 自动获得
通用 CRUD API + 物理表 + 权限点 + AI 可查（Schema 知识同步）。兑现"低代码 × AI"核心承诺。

## 2. 数据模型（openforge-metadata 服务，V1）

```sql
CREATE TABLE meta_object (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    object_key    VARCHAR(64)  NOT NULL,     -- API 路径段与表名后缀: equipment
    display_name  VARCHAR(128) NOT NULL,
    table_name    VARCHAR(64)  NOT NULL,     -- dyn_equipment（dyn_ 前缀隔离自定义对象）
    status        VARCHAR(20)  NOT NULL DEFAULT 'DRAFT',  -- DRAFT/PUBLISHED
    version       INT          NOT NULL DEFAULT 1,
    tenant_id     BIGINT       NOT NULL DEFAULT 0,
    created_by    BIGINT, created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_meta_object_key UNIQUE (object_key)
);

CREATE TABLE meta_field (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    object_id     BIGINT       NOT NULL,
    field_key     VARCHAR(64)  NOT NULL,     -- 列名（snake_case，白名单校验）
    display_name  VARCHAR(128) NOT NULL,
    field_type    VARCHAR(20)  NOT NULL,     -- STRING/NUMBER/DATE/BOOLEAN/REFERENCE
    required      SMALLINT     NOT NULL DEFAULT 0,
    max_length    INT,                       -- STRING 列宽
    ref_object    VARCHAR(64),               -- REFERENCE 指向的 object_key
    ref_field     VARCHAR(64),               -- 引用展示字段（默认 id）
    sort_order    INT NOT NULL DEFAULT 0,
    CONSTRAINT uk_meta_field UNIQUE (object_id, field_key)
);
-- 发布历史（含生成的 DDL 与快照，供回溯与 AI 溯源）
CREATE TABLE meta_object_version (
    id BIGINT ..., object_id, version, definition JSON, ddl_text TEXT,
    published_by, published_at, UNIQUE(object_id, version)
);
```

**类型映射**：STRING→VARCHAR(max_length 默认 255)、NUMBER→NUMERIC(18,4)、DATE→TIMESTAMP、
BOOLEAN→SMALLINT、REFERENCE→BIGINT（值=被引对象记录 id）。
所有表自动附加标准列：id/tenant_id/created_by/created_at/updated_by/updated_at/deleted。

## 3. 核心 API

```
# 建模（meta:manage 权限）
POST   /api/v1/meta/objects                 {objectKey, displayName, fields[]}
PUT    /api/v1/meta/objects/{id}            草稿可改（已发布出新版本）
POST   /api/v1/meta/objects/{id}/publish    发布=生成并执行 DDL+建权限点+同步知识
GET    /api/v1/meta/objects                 列表（含状态/字段数）

# 动态 CRUD（发布后即刻可用；鉴权 @RequirePermission("{objectKey}:view/create/update/delete")）
POST   /api/v1/objects/{objectKey}/records          创建（字段按元数据校验+REFERENCE 存在性）
GET    /api/v1/objects/{objectKey}/records/{id}
GET    /api/v1/objects/{objectKey}/records?filter={field:eq,value}&page=&sort=
PATCH  /api/v1/objects/{objectKey}/records/{id}
DELETE /api/v1/objects/{objectKey}/records/{id}     软删
```

## 4. 安全红线（DDL 与查询生成）

1. **标识符白名单**：objectKey/fieldKey 必须匹配 `^[a-z][a-z0-9_]{2,40}$` 且非 SQL 保留字
   （内置黑名单表）；表名强制 `dyn_` 前缀——生成的 DDL 只做 CREATE TABLE IF NOT EXISTS /
   ADD COLUMN，**永不 DROP/RENAME/CHANGE**（破坏性变更走新版本表迁移方案，本期不支持）；
2. **动态查询**：filter 仅支持白名单字段的 eq/like/in，参数化绑定，拼装层走
   AI 网关 sql_gateway 同款思路（结构化构造，非字符串拼接用户输入）；
3. **权限**：发布时自动创建 `{objectKey}:view/create/update/delete` 四权限点；
   动态 CRUD 用编程式校验（非注解——code 运行时从元数据取注解值）。

## 5. 发布流水线（建模→DDL→AI 闭环）

```
publish(objectId)
 → 校验（字段合法性/引用闭合/至少一个展示字段）
 → 生成 DDL（CREATE TABLE IF NOT EXISTS dyn_xxx ...；已有表则 ADD COLUMN IF NOT EXISTS）
 → 执行 DDL（Flyway 之外的安全通道：专用账号仅授权 dyn_ 前缀 DDL）
 → 写 meta_object_version（definition + ddl 快照）
 → 创建权限点 ×4（HTTP 调 auth /internal）
 → 发 schema.migrated 事件（HTTP 调 knowledge /internal/items：
    表结构描述入知识库 → AI 网关 nl2sql 的白名单+描述表自动登记 → 新对象即刻可被自然语言查询）
 → 状态 PUBLISHED，version+1
```

## 7. 验收标准（F2 Definition of Done）

1. 界面建模"设备台账"（含名称/位置/状态/REFERENCE 到 part）→ 发布 → 无后端代码变更；
2. `POST /api/v1/objects/equipment/records` 可写、分页过滤可查、权限四点生效、无权 403；
3. AI 网关 `sql/validate` 对 `SELECT * FROM dyn_equipment` 返回 allowed（白名单自动登记）；
4. Testcontainers：建模→发布→CRUD 全链路在真实 PG 上绿。

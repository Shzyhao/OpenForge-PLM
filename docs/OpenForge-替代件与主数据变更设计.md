# OpenForge 替代件与主数据变更设计

> 物料域专项：BOM 替代组 + 统一变更中心 + 有效期三态标识 ｜ 基于 v1.12.2 现状
> 版本：v1.1 ｜ 状态：**实施中（刀 1 已交付——替代组/行号/升版/diff 补齐/D7；刀 2 变更中心、刀 3 三态标识待实施）** ｜ 更新日期：2026-09-05
> 关联：《OpenForge-开发文档》3.1 / 3.2 / 4.3、《OpenForge-会话交接》工程约定、《OpenForge-性能与容量画像》§5

## 1. 需求梳理（原始需求结构化）

| # | 需求 | 要点 |
|---|------|------|
| R1 | BOM 明细替代件 | BOM1 中明细 A 可存在替代件 B/C/D；替代件不产生额外用量，与主件共享需求数量 |
| R2 | 替代件可变更 | 替代组支持增删改与优先级调整；**已发布 BOM** 的替代组调整须可追溯、可恢复 |
| R3 | 有效期三态标识 | 有效期**不做展开过滤**；按 有效 / 即将到期（临近一个月）/ 过期 三态以不同颜色标识 |
| R4 | 物料禁用/启用 | 禁用的物料不能再被新 BOM/替代组引用；启用恢复可用；禁用/启用以**变更**形式操作 |
| R5 | 变更整合一个模块 | 替代件变更 + 物料禁用启用变更整合到**同一模块**，方便查找 |
| R6 | 关联补齐项（随本专项落地） | BOM 行号 position、BOM 升版流程、diff 补齐（位号/属性/替代组）、引用校验收紧 |

R6 说明：行号与升版是 R2 的载体（变更单要能精确定位"哪一行"、结构性变更要有版本通道），随刀 1 一并落地；溯源见 §8 决策 D2。

## 2. 现状盘点（v1.12.2 差距）

| 能力 | 现状 | 差距 |
|------|------|------|
| 替代件 | `BomLine.usageType` 含 ALTERNATE 枚举值 | 纯标记、无"替代谁"的指向，无替代组模型，展开/反查/对比全不感知 |
| BOM 行 | 自增 id，无业务行号 | 变更单无法精确引用"第几行" |
| BOM 版本 | version 硬编码 `A/1`，RELEASED 为终态 | 无升版动作，compare 支持双 bomId 但用户造不出第二个版本 |
| BOM diff | 仅按 childPartId 比数量 | 位号/属性/usageType 变更不进 diff 清单 |
| 有效期 | `bom_line.effective_from/to` 字段在库 | 零消费：展开不过滤、界面无标识 |
| 物料禁用 | 状态机已含 `RELEASED ⇄ FROZEN`（StateMachine.PART） | 无 API 入口、无引用拦截、无业务界面 |
| 变更模块 | 仅通用 ECR（SUBMITTED/APPROVED/REJECTED + affectedItems JSON） | 无类型区分、审批通过后无执行动作、无法承载"审批后生效"的变更 |
| 前端 | BomPage 行编辑为平表；ChangePage 单一 ECR 列表 | 无替代组交互、无类型化变更视图、无三态标识 |

## 3. 总体方案

```
┌─────────────────────────────────────────────────────────────────┐
│  统一变更中心（openforge-change 扩展，R5）                          │
│  change_type: GENERIC / SUBSTITUTE_CHANGE / PART_STATE_CHANGE    │
│  审批通过 → 同步 Apply（替代组原位生效 / 物料状态流转）→ apply_state │
└──────────────┬──────────────────────────────┬───────────────────┘
               │ 替代变更(已发布BOM)            │ 禁用/启用变更
┌──────────────▼──────────────┐  ┌────────────▼──────────────────┐
│ BOM 替代组（openforge-material）│  │ 物料禁用启用（复用既有状态机）      │
│ bom_line_substitute 从表      │  │ RELEASED ⇄ FROZEN              │
│ 草稿直改 / 发布版走变更中心      │  │ 禁用后新增引用拦截                │
│ 行号 position / 升版 revise   │  │                                │
└──────────────┬──────────────┘  └────────────────────────────────┘
               │ lines/expand/where-used 响应下发
┌──────────────▼─────────────────────────────────────────────────┐
│ 有效期三态标识（后端计算 validityStatus，前端只渲染颜色）             │
│ 有效(绿) / 即将到期≤30天(琥珀) / 过期(红) / 未生效(灰，可裁剪)        │
└─────────────────────────────────────────────────────────────────┘
```

## 4. 数据模型设计

> 迁移落位遵循 #98 资源目录化（`db/migration/<svc>/`）；DDL 以 H2（dev/mono）与 PostgreSQL（prod）双兼容写法为准，此处表达结构意图。

### 4.1 material V4__bom_line_substitute.sql

```sql
-- 行号：变更单引用与 diff 对位的锚点
ALTER TABLE bom_line ADD COLUMN position INT;              -- 回填按 bom_id 分组、id 升序 1..n
ALTER TABLE bom_line ALTER COLUMN position SET NOT NULL;

-- 替代组：主件行的从表（决策 D1）
CREATE TABLE bom_line_substitute (
    id                 BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    bom_line_id        BIGINT        NOT NULL,              -- 主件行
    substitute_part_id BIGINT        NOT NULL,              -- 替代件
    priority           INT           NOT NULL DEFAULT 1,    -- 替代顺序，小者优先
    qty_coefficient    NUMERIC(10,4) NOT NULL DEFAULT 1,    -- 替代件用量 = 主件用量 × 系数
    condition_json     TEXT,                                -- 预留：替代条件（日期段/客户等），本期不定语义
    last_change_id     BIGINT,                              -- 最近一次生效变更单（追溯锚点）
    tenant_id          BIGINT        NOT NULL DEFAULT 0,
    created_at         TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_bom_sub UNIQUE (bom_line_id, substitute_part_id)
);
CREATE INDEX idx_bom_sub_part ON bom_line_substitute (substitute_part_id);  -- 替代件反查
```

数量语义（核心不变量）：替代件**不额外产生需求**。展开/成本/需求口径只认主件行 quantity；替代件仅声明"缺料时可按系数顶替主件"。

### 4.2 change V2__change_type.sql

```sql
ALTER TABLE change_request ADD COLUMN change_type  VARCHAR(20) NOT NULL DEFAULT 'GENERIC';
ALTER TABLE change_request ADD COLUMN payload      TEXT;   -- 类型化明细 JSON（含前后快照）
ALTER TABLE change_request ADD COLUMN apply_state  VARCHAR(10);  -- PENDING/APPLIED/FAILED，仅可执行类型
ALTER TABLE change_request ADD COLUMN apply_result TEXT;   -- 执行结果 / 失败原因
-- 存量 ECR 回填 GENERIC，apply_state 为 NULL
```

### 4.3 类型化 payload 契约

| change_type | payload 结构 | apply 动作 |
|-------------|-------------|-----------|
| GENERIC | 现有 ECR 字段不变（reason/affectedItems） | 无（审批即结束） |
| SUBSTITUTE_CHANGE | `{bomId, bomNumber, lineId, mainPartId, before:[{substitutePartId,priority,qtyCoefficient}], after:[…], note}` | 应用到已发布 BOM 替代组（见 §5.4） |
| PART_STATE_CHANGE | `{partId, partNumber, targetState: FROZEN\|RELEASED, whereUsedSnapshot}` | 物料状态流转（见 §5.4） |

payload 即审计凭证：`before/after` 全量快照随变更单落库，替代表上的 `last_change_id` 反向锚定，追溯不需要额外审计表。

### 4.4 有效期三态（无新表）

后端以 `bom_line.effective_from/to` + 服务器日期实时计算 `validityStatus`，随响应下发，前端不做日期运算（口径单一，避免两端规则漂移）：

| validityStatus | 判定 | 颜色 |
|----------------|------|------|
| VALID 有效 | effective_to 为空 或 > today+30 | 绿 |
| EXPIRING 即将到期 | today ≤ effective_to ≤ today+30（30 可配 `openforge.material.validity.expiring-days`） | 琥珀 |
| EXPIRED 过期 | effective_to < today | 红 |
| NOT_YET_EFFECTIVE 未生效 | effective_from > today | 灰（可裁剪项，评审定夺） |

## 5. 后端设计

### 5.1 替代组 API（openforge-material，门禁与行维护一致：仅 DRAFT BOM）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/boms/{bomId}/lines/{lineId}/substitutes` | 新增替代件 `{substitutePartId, priority, qtyCoefficient}` |
| GET | `/api/v1/boms/{bomId}/lines/{lineId}/substitutes` | 替代组列表（按 priority 排序） |
| PUT | `/api/v1/boms/{bomId}/lines/{lineId}/substitutes/{subId}` | 调整优先级/系数 |
| DELETE | `/api/v1/boms/{bomId}/lines/{lineId}/substitutes/{subId}` | 移除替代件 |

- `GET /lines`、`expand`、`where-used` 响应内联 `substitutes[]` 与 `validityStatus`（DTO 演进：BomLineResponse）。
- 主件行删除 → 级联删除替代组；行号 position 由服务端维护（新增追加尾位，删除后紧缩）。

### 5.2 展开 / 反查 / 对比联动

| 功能 | 改造 |
|------|------|
| expand | BomNode 增 `substitutes[]`（partId/partNumber/name/priority/qtyCoefficient）；环检测复用现有祖先路径逻辑，**替代件也纳入环检测**（替代件=父件祖先则拒绝）。不做"按替代优先级择一展开"（非目标，见 §9） |
| where-used | 结果区分 `usageRole: MAIN\|SUBSTITUTE`；替代件反查返回其作为替代的主件行定位（bomId/bomNumber/主件件号） |
| compare | 结构 diff 仍按 childPartId 对位；新增变更类型 SUBSTITUTE_ADDED / SUBSTITUTE_REMOVED / SUBSTITUTE_CHANGED；并补齐 REFDES_CHANGED / USAGE_TYPE_CHANGED / ATTR_CHANGED（R6）。输出按 position 排序 |

### 5.3 BOM 升版 revise（R2 的结构性变更通道）

- `POST /api/v1/boms/{id}/revise`：仅 RELEASED 可升版。生成新 Bom（version 次版本 +1：`A/1 → A/2`），深拷贝行 + 替代组 + position，状态 DRAFT；原 BOM 保持 RELEASED 不可变（审计与 diff 基线）。
- 同一父件允许多版本共存（旧版 RELEASED + 新版 DRAFT）；版本主版本规则 M3 与物料版本策略对齐。
- 结构性变更（增删主件行/改数量）必须走升版，不得直接改发布版（决策 D2 的边界）。

### 5.4 统一变更中心（openforge-change 扩展）

**状态模型**：变更单状态机不变（SUBMITTED → APPROVED/REJECTED，沿用工作流引擎挂接），新增执行子状态 `apply_state` 与审批解耦：

```
SUBMITTED ──审批通过──▶ APPROVED ──Apply 成功──▶ apply_state=APPLIED
                        │
                        └──Apply 失败──▶ apply_state=FAILED ──人工重试──▶ APPLIED
                           POST /api/v1/changes/requests/{id}/apply
```

**Apply 分发**（EcrService.approve 钩子，按 changeType 路由）：

- `SUBSTITUTE_CHANGE` → 调 material 服务应用到**已发布 BOM** 的替代组（原位应用，不动版本号）：重放校验（主件行仍存在、替代件状态仍合规）→ 全量替换该行替代组（以 after 快照为准）→ 回写 `last_change_id`。
- `PART_STATE_CHANGE` → 调 material 服务执行 `RELEASED⇄FROZEN`（复用 StateMachine.PART 校验）；提交时自动调 where-used 生成影响清单快照入 payload（禁用前证据，呼应开发文档 §3.2 影响分析）。
- `GENERIC` → 无 apply。

**为什么同步应用而非事件驱动**：审批通过需要确定性结果反馈（apply_state 原子可见），异步会造成"已批准但未生效"窗口并引入幂等补偿成本；变更执行是低频操作，同步开销可接受（性能画像设计期四问口径）。跨服务调用沿用现有 client 模式（同 NumberClient/WorkflowClient + 内部令牌）。

**为什么扩展 change 模块而非新建服务**：模块注册表/网关路由/菜单/权限/冒烟链路全部现成（决策 D5）；"方便找"由前端统一视图兑现（§6.2），不靠新微服务。

### 5.5 校验规则汇总（实现对照用）

| 场景 | 规则 | 落地刀 |
|------|------|--------|
| BOM 行引用子件 | 非 DRAFT（行为收紧，见 D7）；FROZEN/PHASED_OUT 拒绝新增引用 | 刀 1 / 刀 2 |
| 新增替代件 | ≠主件；同行内不重复（uk 兜底+前置友好报错）；非 DRAFT、非 FROZEN/PHASED_OUT；不得为 BOM 父件祖先（环检测）；qty_coefficient > 0；单行替代件防呆上限默认 10（可配） | 刀 1 / 刀 2 |
| 禁用变更 | 目标物料须 RELEASED；**已有引用不阻断禁用**（先禁料再清 BOM 是真实业务顺序），但变更单自动附影响清单；禁用后新增引用被 §5.5 上两行拦截 | 刀 2 |
| 启用变更 | 目标物料须 FROZEN | 刀 2 |
| 替代变更（发布版） | Apply 时重放 §5.5 全部替代件校验；主件行已不存在则 FAIL 并落原因 | 刀 2 |
| 位号 | 同 BOM 内位号重复仅告警不阻断（M2 简化） | 刀 1 |

### 5.6 有效期计算下发

material 服务在 `lines / expand / where-used` 响应统一计算 `validityStatus`（§4.4）；不入库、不建索引（实时判定，行数规模下无性能风险——BOM 行单表规模见性能画像 §3）。

## 6. 前端设计

### 6.1 BomPage：替代组交互

- 行表格新增：**行号**列（只读 position）、**替代**列（无替代显示"-"；有替代显示数量徽标，展开行显示替代组子表：件号/名称/优先级/系数/操作）。
- 草稿 BOM：编辑对话框内含替代组管理（增删改、优先级上下移、系数录入）。
- 发布版 BOM：替代列旁提供"**发起替代变更**"按钮 → 跳转变更中心并预填 bomId/lineId（唯一通道，草稿直改不提供该按钮）。

### 6.2 ChangePage → 变更中心（R5 的"一个模块"）

- 列表按 **changeType 筛选**（全部 / 替代件变更 / 物料禁用启用 / 通用 ECR），stats 按类型计数。
- 新建表单按类型切换：
  - 替代件变更：选 BOM → 选行 → 以交互表格编辑 before/after 替代组；
  - 禁用/启用：选物料 → 自动展示 where-used 影响清单 → 选目标状态；
  - 通用 ECR：现有表单不动。
- 详情页类型化渲染：替代变更以 before/after diff 样式呈现；`apply_state=FAILED` 显著标红并提供"重试执行"按钮。
- 菜单归属现有"变更"模块，仅页内改造（不动模块注册表）。

### 6.3 MaterialPage：禁用/启用入口

- 状态列 FROZEN 显示"已禁用"徽标；"发起禁用变更"仅 RELEASED 物料可见、"发起启用变更"仅 FROZEN 可见 → 跳转变更中心预填（与 §5.5"唯一入口"一致）。

### 6.4 三态颜色 token（沿用 #77 品牌 token 体系，暗色模式同步适配）

| token | 亮色基调 | 用途 |
|-------|---------|------|
| `--status-valid` | 绿 | 有效 |
| `--status-expiring` | 琥珀 | 即将到期 ≤30 天 |
| `--status-expired` | 红 | 过期 |
| `--status-inactive` | 灰 | 未生效（若保留） |

呈现形式为"色点 + 文字徽标"，不只靠颜色（色弱可用性）。应用位置：BOM 行列表、展开树、where-used 结果、变更中心受影响对象。

## 7. 权限点

| 权限点 | 类型 | 说明 | 状态 |
|--------|------|------|------|
| bom:view / bom:update | OPERATION | 替代组编辑归入 BOM 行维护权限，**不新增**（升版权限细分可后续评审，默认并入 bom:update） | 沿用 |
| bom:revise | OPERATION | 升版产生新版本对象，建议独立权限点（默认给 ENGINEER 及以上）；若评审判定过细则并入 bom:update | 新增（评审项） |
| change:create / change:approve | OPERATION | 两类新变更沿用变更域现有权限点，不按 type 细分（M2 简化） | 沿用 |
| change:retry-apply | OPERATION | FAILED 重试执行；默认与 change:approve 同绑（审批人才可重试） | 新增 |

## 8. 关键决策记录

| # | 决策 | 理由 | 升级路径 |
|---|------|------|---------|
| D1 | 替代组做主件行**从表**（bom_line_substitute），不做独立 BOM 行 | 替代件不产生额外用量，独立行会使展开/成本/需求算重；与"同 BOM 子件唯一"约束冲突；下游（diff/导入/反查）改从表一处，改独立行则全链路组感知 | 全局替代关系（物料主数据层 A⇄B）后置单独专项 |
| D2 | 已发布 BOM 的替代变更 = 变更单审批 + **原位应用**（不动版本号），前后快照入 payload 作审计 | 替代组不改变 BOM 结构（行集合/数量/层级），属"供应保障属性"；二供调整高频，强制升版成本不成比例。结构性变更仍必须走升版 | M4 ECO/受控区落地后可收敛为标准变更对象 |
| D3 | 禁用/启用复用既有 `RELEASED⇄FROZEN` 状态机，**唯一入口 = 变更单**（物料页只留发起跳转） | 一扇门原则（R5"方便找"）；状态机零改动；禁用可恢复与 PHASED_OUT 终态废止语义分开 | 废止（PHASED_OUT）流程后置 |
| D4 | 有效期**不做展开过滤**，三态标注（+未生效灰色可选） | 用户决策 2026-09-05：过滤改变展开结果语义，标注只改观感，风险面小 | 若后续 MRP 择料需要，再加过滤开关 |
| D5 | 变更中心 = 扩展现有 change 模块，不新建服务 | 注册表/路由/菜单/权限/冒烟链路现成；新建服务与 mono 刀 2 同类"收益≈零、侵入不成比例" | 类型膨胀（≥5 种）再评估拆分 |
| D6 | 审批与执行分离（apply_state），**同步应用 + 人工重试**，不走 B2 事件 | 避免"已批准未生效"窗口与幂等补偿；低频操作同步可接受 | 若出现批量变更场景再引入异步队列 |
| D7 | 被引用子件收紧为**非 DRAFT**（行/替代同规则） | 发布 BOM 引用草稿件使发布语义失效；现 addLine 只查存在性属缺口 | —— 行为变更，需在 PR 描述与冒烟中显式验证存量数据兼容 |

## 9. 边界与非目标

- **展开不过滤有效期**（D4，明确不做）。
- 全局替代关系（物料主数据层替代矩阵）、替代条件 `condition_json` 语义（仅建字段）。
- 按 替代优先级自动择料展开（MRP 式）、替代件的部分替代/百分比替代。
- ECO/ECN 对象与变更受控区 Working 模型（开发文档 §3.2 完整版）→ M4。
- 行级损耗率、行单位、PHANTOM 虚拟件 → 后置。
- 变更审批流不重做（沿用 WorkflowClient 挂接现有工作流引擎）。
- 本专项不新增 B2 事件类型（change 域事件已覆盖）；物料状态变更事件待下游 ERP 推送需要时扩展。

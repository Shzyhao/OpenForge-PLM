## 2. 架构目标与约束

### 2.1 质量属性目标（按优先级排序）

| # | 质量属性 | 目标 | 架构对策 |
|---|----------|------|----------|
| 1 | **可配置性（低代码）** | 70% 的长尾需求（自定义对象、表单、流程、报表、集成）通过配置交付，零代码上线 | 元数据驱动内核（第 5 章） |
| 2 | **可扩展性** | 水平扩展无状态服务；AI 负载独立伸缩 | 微服务 + K8s HPA，AI 独立节点池 |
| 3 | **可用性** | 核心链路 99.9%；AI 故障不影响主流程 | 服务多副本 + AI 熔断降级 |
| 4 | **安全性** | PLM 数据为企业核心资产；AI 触达数据必须受控 | 分层安全 + SQL 安全网关（见 10 章） |
| 5 | **可追溯性** | 版本链、变更链、审批链、审计链全留痕 | 事件溯源式审计、不可变日志 |
| 6 | **性能** | 列表 P95 < 800ms；万行 BOM 展开 < 3s | 缓存、读写分离、虚拟滚动 |
| 7 | **可维护性** | 核心域与扩展域解耦，边界清晰 | 分层依赖规则（见 6.3） |

### 2.2 关键约束

- 浏览器端交付（B/S），需兼容内网离线部署（私有化）与 SaaS 两种形态；
- 敏感场景（军工/汽车图纸）要求大模型私有化可选，数据不出域；
- 需与存量 ERP/MES/OA 集成，集成协议不可控（REST/DB/文件/中间表均可能出现）；
- 团队为 Java + Python + 前端混合编制，架构须容忍异构技术栈并存。

## 3. 总体架构

### 3.1 架构风格

系统采用三种架构风格的组合：

1. **微服务 + 事件驱动**：业务域独立服务，跨域协作走异步事件（RocketMQ），保证最终一致性与知识自动沉淀；
2. **元数据驱动（Metadata-Driven）**：对象模型、界面、流程、规则、集成、AI 配置全部元数据化，由平台运行时解释执行——这是低代码能力的架构根基；
3. **混合编程模型**："核心域专业代码 + 扩展域低代码配置 + Pro-Code 扩展点"，稳定性与灵活性兼得。

### 3.2 分层总览

```
┌────────────────────────── 用户层 ──────────────────────────┐
│   PC Web(React SPA) │ 移动H5(待办/审批) │ 第三方系统(OpenAPI) │
├────────────────────────── 接入层 ──────────────────────────┤
│        API Gateway：JWT认证 / RBAC / 限流 / 路由 / 灰度 / 审计 │
├─────────────────────────────────────────────────────────────┤
│                    应用层（业务服务域）                        │
│  物料BOM │ 文档 │ 变更ECM │ 项目 │ (搜索/通知/预览转换：规划)  │
├─────────────────────────────────────────────────────────────┤
│                          平台层                               │
│  ┌── 低代码平台域 ──────────────┐  ┌── AI 中台域 ──────────┐ │
│  │ 元数据内核(元数据中心)        │  │ 模型网关(多LLM接入)    │ │
│  │ 设计器集群(对象/表单/流程/    │  │ Agent编排              │ │
│  │   规则/报表/集成/AI配置)     │  │ Text-to-SQL安全网关    │ │
│  │ 动态对象运行时(通用CRUD)      │  │ 知识加工管道(RAG)      │ │
│  │ 流程引擎 │ 规则引擎           │  │ Schema元数据同步       │ │
│  │ 连接器运行时(集成编排)        │  └───────────────────────┘ │
│  └─────────────────────────────┘                            │
│  基础服务：认证/组织权限 │ 编号规则 │ 字典 │ 消息 │ 文件存储     │
├─────────────────────────────────────────────────────────────┤
│                          数据层                               │
│  PostgreSQL+pgvector(当前) │ RocketMQ │ Prometheus/Grafana     │
│  (Redis/Milvus/Neo4j/ES/MinIO：路线，按规模启用)               │
└─────────────────────────────────────────────────────────────┘
        两类纵向能力贯穿所有层：① 低代码/元数据解释执行 ② AI 增强
```

**分层依赖规则**：只允许上层依赖下层、同层仅通过事件/接口协作；低代码平台域与 AI 中台域是"能力供体"，被应用层依赖、不反向依赖应用层。

### 3.3 核心域与扩展域的划分策略

```
┌──────────────────────────────────────────────┐
│ 扩展域(低代码配置交付, 70%长尾需求)              │
│  自定义业务对象(设备台账/模具/工装…)             │
│  个性化表单/列表页/报表                          │
│  二级部门审批流、轻量业务流程                     │
│  与周边系统的集成编排                            │
├──────────────────────────────────────────────┤
│ 核心域(专业代码, 保证性能与业务深度, 30%高价值)    │
│  物料/BOM(十万行展开/对比) 文档(版本/检出入)      │
│  变更ECR-ECO-ECN 受控区  CAD解析  AI数据操作     │
├──────────────────────────────────────────────┤
│ 平台域(内核, 低代码+AI 基础设施)                 │
│  元数据内核 流程引擎 规则引擎 AI网关 知识库        │
└──────────────────────────────────────────────┘
```

原则：**越靠近内核越稳定（代码交付、季度级迭代），越靠近边缘越灵活（配置交付、天级上线）**。核心域对象（如物料）同样在元数据中心注册，享受低代码的界面/流程配置能力，但业务逻辑由专业服务实现——"模型注册在平台、逻辑留在领域"。

## 5. 低代码平台架构（核心）

### 5.1 能力总览：七大设计器 + 三大运行时

```
┌─────────────────── 设计器集群（低代码开发界面） ───────────────────┐
│ ①对象建模器   ②表单设计器    ③列表页设计器   ④流程设计器            │
│ ⑤规则设计器   ⑥报表设计器    ⑦集成编排器     (+AI配置器)           │
└───────────────────────────┬───────────────────────────────────┘
                            │ 产出均为"元数据制品"(版本化JSON/XML)
┌───────────────────────────▼───────────────────────────────────┐
│                     元数据内核（Metadata Kernel）                │
│  统一元数据模型 │ 元数据中心(存储/版本/依赖图) │ 变更广播 │ 兼容性检查│
└───────────────────────────┬───────────────────────────────────┘
                            │ 解释执行
┌─────────────── 运行时集群 ──┴──────────────────────────────────┐
│ 动态对象运行时(通用CRUD) │ 流程+规则引擎 │ 连接器运行时            │
└───────────────────────────────────────────────────────────────┘
                            │ Pro-Code 扩展点(见5.5)
┌───────────────────────────▼───────────────────────────────────┐
│ 扩展体系：自定义前端组件 │ 服务端逻辑插件 │ 自定义连接器 │ 脚本沙箱  │
└───────────────────────────────────────────────────────────────┘
```

### 5.2 元数据内核

一切低代码能力的地基是**统一元数据模型**——九类元数据全部登记在元数据中心，版本化存储、运行时缓存、变更广播：

| 元数据类型 | 内容 | 主要消费方 |
|------------|------|-----------|
| 对象模型 | 实体、字段（类型/校验/字典）、关系、约束、索引、状态机声明 | 动态对象运行时、DDL 生成器、**Schema 知识库** |
| 表单 | 表单 JSON Schema（字段绑定/联动/校验） | 表单渲染器、流程任务页 |
| 列表页 | 列定义、筛选器、行操作、批量操作 | 列表渲染器 |
| 流程 | 流程定义 JSON（节点+边）+ 条件规则 + 表单绑定 | 流程引擎 |
| 规则 | 决策表 / 表达式（校验、计算、路由变量） | 规则引擎 |
| 报表 | 数据集（安全查询）+ 图表编排 | 报表运行时 |
| 连接器 | 端点、认证、字段映射、编排步骤 | 连接器运行时 |
| AI 配置 | Prompt 版本、Agent 工具集、抽取 Schema | AI 中台 |
| 权限 | 权限点、角色、ACL（对象×主体×动作） | 网关 + 各运行时 |

**元数据中心职责**：

1. **版本化存储**：每次发布生成不可变版本（快照），运行时按版本加载，支持一键回滚；
2. **依赖图**：维护"对象 ← 表单 ← 流程 ← 报表"的引用关系，用于发布前影响分析；
3. **兼容性检查**：对象模型变更（删字段/改类型）时校验在途流程实例与历史数据兼容性，不兼容则阻断并给出迁移建议；
4. **变更广播**：发布后经 RocketMQ 广播 `meta.published`，各运行时刷新本地缓存（秒级生效，无需重启）；
5. **多环境流转**：元数据制品可导出为包（JSON 打包），在 DEV→TEST→PROD 间提升，与代码发布解耦。

### 5.3 对象建模器与 DDL 同步链路

对象建模器让实施人员声明业务对象（如"设备台账"），由平台生成物理表并打通 AI 知识闭环：

```
设计器: 定义对象(字段/关系/校验/状态机)
 → 元数据中心: 兼容性检查 + 依赖影响分析
 → DDL生成器: 产出 Flyway 格式迁移脚本(仅白名单schema)
 → 迁移执行 → 发出 schema.migrated 事件
      ├─▶ ① Schema知识库自动同步(开发文档5.3.2: 向量化+图谱+术语)
      ├─▶ ② 元数据缓存广播, 动态对象运行时即时提供通用CRUD API
      └─▶ ③ AI 能力自动可用: Text-to-SQL立即理解新对象(无需训练)
```

这条链路是本系统"低代码 × AI"的闭环亮点：**新对象建模发布后，零代码获得 CRUD API、可配置界面，且 AI 助手立刻能查询/操作它**——因为 AI 依赖的元数据知识库在同一事件中完成同步。

**动态对象运行时通用 API**（按对象元数据自动生效，无需写后端代码）：

```
POST   /api/v1/objects/{objectKey}/records          创建
GET    /api/v1/objects/{objectKey}/records/{id}      详情
GET    /api/v1/objects/{objectKey}/records?filter=…  分页/筛选/排序
PATCH  /api/v1/objects/{objectKey}/records/{id}      更新
POST   /api/v1/objects/{objectKey}/records/bulk      批量(走L2确认)
```

### 5.4 各设计器要点

| 设计器 | 要点 | 复用规范 |
|--------|------|----------|
| 表单/列表设计器 | 自研界面设计器（#49）：字段序/可见/标签/列宽定制为布局制品，零依赖；数据页按元数据渲染表单/表格 | 布局随对象元数据存储，动态数据页直接应用 |
| 流程设计器 | 自研 SVG 画布（零依赖，#82）：节点拖拽/连线/属性面板/自动布局，与引擎 JSON 定义双向同步（bpmn-js 评估后否决）；会签/加签/驳回策略配置 | 详见开发文档第 6 章 |
| 规则设计器 | 决策表（非技术人员可读）+ 表达式双模式；规则可被流程网关/对象校验/报表复用 | 规则执行有版本快照，保证审计可复现 |
| 报表设计器 | 拖拽维度/指标；数据集基于安全查询（强制行级权限），禁止自由 SQL | 报表缓存 + 订阅推送 |
| 集成编排器 | 可视化编排连接器（触发器→转换→调用→错误重试），见第 8 章 | — |
| AI 配置器 | Prompt 版本管理、抽取 Schema 维护、Agent 工具集开关 | 供 AI 中台热加载 |

### 5.5 Pro-Code 扩展体系（低代码的天花板突破）

低代码不可能覆盖 100% 场景，架构上提供四类受控扩展点，形成"配置不动代码、代码不侵入平台"的分层：

| 扩展点 | 形式 | 隔离机制 |
|--------|------|----------|
| 前端自定义组件 | 微件规范（props/events/slots + 打包为 ESM），注册进物料面板 | 组件级错误边界，崩溃不影响整页 |
| 服务端逻辑插件 | 对象生命周期钩子（beforeCreate/afterUpdate/onStateChange…），Java SPI 实现或消息订阅 | 插件超时熔断，失败不阻断主事务（可配） |
| 脚本沙箱 | 轻量逻辑（字段计算、格式化）用 JS 脚本，GraalJS/QuickJS 沙箱执行 | CPU/内存/时长配额；禁止 IO，白名单 API 注入 |
| 自定义连接器 | 实现 Connector SPI（healthcheck/map/execute），注册进集成编排器 | 独立部署单元，故障隔离 |

### 5.6 低代码制品生命周期（治理）

```
草稿 ──▶ 预览(沙箱试运行,模拟数据) ──▶ 审批(走流程引擎,自举)
 ──▶ 发布(生成不可变版本+快照) ──▶ 灰度(按部门/用户比例)
 ──▶ 全量 ──▶ (问题)一键回滚到上一版本快照
```

- 低代码变更本身也走系统内流程审批（平台自举，治理动作与业务动作同构）；
- 发布前强制展示**影响分析**：受影响的表单/流程/报表/AI Prompt 清单；
- 全量审计：谁在何时改了哪个元数据制品的哪个属性，diff 可查。

### 5.7 低代码权限模型

| 角色 | 能力 |
|------|------|
| 低代码管理员 | 管理设计器准入、发布审批流配置、回滚 |
| 空间开发者 | 在授权"开发空间"内设计对象/表单/流程（不能越空间引用） |
| 业务管理员 | 只可调整范围内流程参与者、表单显隐等轻配置 |
| 最终用户 | 仅消费运行时 |

开发空间与知识空间对齐（同一租户/部门边界），元数据可见性同样受 ABAC 约束。

### 5.8 AI 辅助低代码（AI × 低代码融合）

AI 中台为设计器提供"生成式开发"能力（复用元数据知识，产出均为**草稿**，人在设计器中确认调整）：

| 能力 | 示例 |
|------|------|
| 自然语言建模 | "创建设备台账对象：编号、名称、位置、状态（在用/停用）、责任人" → 生成对象模型草稿（字段类型/字典自动推断） |
| 自然语言生成表单 | 按对象模型 + 口述分组规则 → 表单 Schema 草稿 |
| 自然语言生成流程 | "三级审批，金额>1万加财务节点" → 流程定义 JSON 草稿 + 规则表达式 |
| 变更摘要 | 元数据 diff → 人话变更说明（供审批人阅读） |
| 反向解读 | 打开陌生流程 → AI 解释每个节点作用（降低接手成本） |

## 6. 应用架构

### 6.1 服务清单与职责

见开发文档 2.2 节（服务清单在此不再重复）。本章补充架构视角的两点：

**部署弹性分级**：

| 级别 | 服务 | 策略 |
|------|------|------|
| 强状态 | workflow、metadata-center | 单分区串行（按流程定义分片），避免实例状态竞争 |
| 一般无状态 | material/doc/change/project/… | 随机多副本，HPA 按 CPU/QPS |
| 重计算 | preview（CAD 转换）、ai-pipeline | 任务队列削峰，按队列深度伸缩 |
| GPU | ai-gateway（私有化大模型时） | 独立节点池，显存利用率伸缩 |

### 6.2 事件清单（核心异步协作）

| 事件 | 生产者 | 消费者 |
|------|--------|--------|
| `schema.migrated` | metadata-center | knowledge(Schema同步)、ai-gateway(上下文刷新) |
| `meta.published` | metadata-center | 各运行时缓存刷新 |
| `object.record.created/updated` | object-runtime | workflow(触发流程)、knowledge(摘要入库) |
| `doc.released` | doc | knowledge、search 索引 |
| `change.closed` | change | knowledge(案例沉淀)、project |
| `task.created/completed` | workflow | notify、统计 |
| `part.released` / `bom.published` | material | connector(推ERP)、search |

### 6.3 依赖规则（架构守护）

- 应用层服务**禁止**直接读写他域数据库，跨域取数走 API 或事件携带数据；
- 低代码平台域与 AI 中台域**禁止**依赖任何业务域（只消费事件与元数据）；
- 依赖方向在 CI 中以 ArchUnit（Java）/ import-linter（Python）强制校验，违规即构建失败。

## 7. 数据架构

### 7.1 存储选型矩阵

| 数据类别 | 存储 | 理由 |
|----------|------|------|
| 业务数据（物料/BOM/变更/流程实例） | PostgreSQL | 事务强一致；JSONB 承载动态属性；分区表承接 BOM 行大表 |
| 元数据（九类制品） | PostgreSQL（jsonb + 版本表） | 与业务库同库不同 schema，事务内一致性 |
| 文件（CAD/Office/附件） | 本地磁盘（当前，租户目录隔离）；MinIO/S3（规划） | 起步零外部依赖；规模化后对象存储归档 |
| 向量（知识/schema_vec） | pgvector（当前：租户 SQL 过滤 + HNSW）；Milvus（路线，千万级） | 单 PG 栈起步，降级零门槛；规模跨千万再引专用向量库（ADR-06） |
| 图谱（知识/表关系） | Neo4j（路线） | 多跳查询（影响分析/Join 路径） |
| 全文索引 | Elasticsearch（路线，当前 PG like/等值过滤） | BM25 + 聚合 |
| 缓存/锁/限流 | Redis（路线，compose extras 预留零代码使用） | 元数据热缓存（当前 JVM 内 TTL 缓存）、检出锁、分布式限流 |
| 事件流 | RocketMQ（默认关闭回退同步 HTTP） | 事务消息、回溯重放 |

### 7.2 数据分层与流转

```
操作数据(OLTP: PG) ──CDC(逻辑复制)──▶ 检索层(ES/向量/图谱, 最终一致, 秒级)
                    └──事件──▶ 知识层(知识库, 异步加工)
                              └──分析层(报表宽表, T+1或准实时)
```

- 检索层与知识层允许短暂滞后（秒~分钟），业务侧不依赖其一致性；
- BOM 行表按 `parent_part_id` 哈希分区 + 历史版本归档至冷表，保障热数据查询。

### 7.3 多租户策略

私有化部署（主形态）= 单租户独占；SaaS 形态 = 共享库 + `tenant_id` 行级隔离 + 独立 schema 可选（大客户）。元数据与知识库均带租户维度，Milvus 标量过滤实现租户隔离。

## 8. 集成架构

### 8.1 集成模式矩阵

| 模式 | 适用 | 实现 |
|------|------|------|
| 同步 API | ERP 查库存、SSO 认证 | 网关路由 + 连接器 |
| 异步事件 | BOM 发布推送、状态回传 | RocketMQ + 连接器消费 + 重试/死信 |
| 文件交换 | 与老系统批量对账 | MinIO 落盘 + 定时任务 + 对账报告 |
| 数据库直连(只读) | 历史系统中间表 | 连接器只读账号，白名单表，禁写 |

### 8.2 连接器规范

```
连接器 = 端点(endpoint+认证) + 映射(字段映射/转换脚本) + 编排(触发/步骤/重试/幂等)
```

- 内置连接器：HTTP/REST、数据库(JDBC 只读)、飞书/企微/钉钉、邮件、SFTP；
- 幂等：外部回调带 `Idempotency-Key`；外呼按业务键防重；
- 可观测：每次集成执行有 trace，失败进死信队列 + 告警 + 人工重放界面；
- 所有外呼数据经**出站脱敏代理**（与 AI 外呼同一条通道），统一管控数据外流。

## 10. 安全架构

> 详细控制项见开发文档第 10 章，此处给出分层视图与新增面。

```
接入安全: TLS1.3 │ WAF │ 网关限流/防重放 │ JWT短时效
应用安全: RBAC+ABAC(数据权限SQL注入式过滤) │ 越权扫描 │ 操作二次确认
平台安全: 低代码治理(配置权限/发布审批/沙箱隔离) ★新
AI安全:   SQL安全网关(五层) │ 权限合成(交集原则) │ 出入站脱敏 │ 模型私有化可选
数据安全: 静态加密 │ 密级标签全程流转 │ 备份容灾 │ 审计不可变
```

**低代码特有的安全面**：脚本沙箱资源配额与 IO 禁令；自定义组件的供应链扫描（上传组件包需签名+扫描）；连接器出站白名单（防 SSRF）；报表数据集强制行级权限；元数据发布审计。

## 12. 架构决策记录（ADR）

| 编号 | 决策 | 备选 | 理由与代价 |
|------|------|------|-----------|
| ADR-01 | 微服务按域拆分，但初期"逻辑服务、可合并部署" | 单体 / 全拆 | 单体迭代快但 AI 域无法独立伸缩；全拆运维成本高。折中：进程可合并，代码与数据边界先行 |
| ADR-02 | 自研精简流程引擎 | Flowable/Camunda | 需深度定制 AI 节点、定义快照、灰度路由；Flowable 二次改造成本高于自研受限内核。代价：需自行补齐超时/补偿等成熟件 |
| ADR-03 | 元数据驱动（核心域代码 + 扩展域配置混合） | 全硬编码 / 全低代码 | 全硬编码无法满足天级交付；全低代码牺牲深度（BOM 十万行展开等）。混合边界见 3.3 |
| ADR-04 | AI 独立 Python 域 | Java 内嵌调用 | AI 生态（LangChain/vLLM）在 Python；独立域故障隔离、GPU 独立伸缩。代价：跨语言链路追踪与部署复杂度 |
| ADR-05 | PostgreSQL 单主库 + 分区 | MySQL / 多库 | JSONB 承接动态属性与元数据；分区承接 BOM 大表。代价：超大规模需引入中间层分片（预留 Citus 路线） |
| ADR-06 | Milvus（千万级）+ pgvector（小规模降级） | 纯 pgvector | 私有化小客户可降级单 PG 栈，降低交付门槛 |
| ADR-07 | 设计器自研内核（流程 SVG 画布/界面设计器，零依赖） | Formily + bpmn-js | 引擎为自有 JSON 定义而非 BPMN 2.0，XML 双向映射层是纯开销 + bpmn.io 水印条款；代价：交互与自动布局自行维护（#82） |
| ADR-08 | 事件驱动知识沉淀 | 定时 ETL | 实时性与业务侵入平衡；代价：事件幂等与乱序处理复杂度 |
| ADR-09 | AI 数据操作坚持"API 通道优先 + SQL 网关白名单" | 开放自然语言直写 | 防绕过业务校验；SQL 通道仅作白名单补充（开发文档 4.7） |
| ADR-10 | 前端设计器独立打包 | 单 SPA | 设计器依赖重、受众小，懒加载隔离 |

## 13. 架构演进路线

> 当前进度（v1.9.0）：阶段一、二的主体已交付（低代码设计器 v1：界面/流程自研零依赖；
> 动态对象运行时 + 建模→DDL→知识库→AI 可查闭环；多租户全链路；事件总线 + outbox 可靠性；
> Nacos 配置中心；pgvector 租户隔离）。阶段三的 Text-to-SQL 安全网关已交付，AI 全域增强与
> 阶段四生态化（连接器/行业模板包/SaaS）为后续方向。

```
阶段一(0-6月): 核心域+基础平台 ── 表单/流程低代码可用(设计器v1)
阶段二(6-12月): 动态对象运行时+连接器 ── 对象建模发布闭环(DDL→知识库→AI可查)
阶段三(12-18月): AI全域增强 ── Text-to-SQL安全网关生产化, AI辅助建模, 知识自适应闭环
阶段四(18月+): 生态化 ── 组件/连接器市场, SaaS多租户, 行业模板包(离散装备/汽配/电子)
```

各阶段架构守护动作：每阶段结束执行一次架构适应度评审（依赖规则扫描、容量压测、故障演练），不符合则先还债再前进。

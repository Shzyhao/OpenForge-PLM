# F2 补充设计：模块注册机制（路线 A4）

> 框架化路线 A4 的实施蓝图 ｜ 状态：已交付（A4-1~A4-4，PR #46/#43/#44/#47） ｜ 更新：2026-08-28
> 上游：《OpenForge-框架化路线》A4/工程备忘1、《OpenForge-架构文档》3.3（平台域/核心域/扩展域）、6.2/6.3

---

## 1. 目标

把"7+1 服务固化"的写死架构变成**模块化的平台底座**：

1. **部署即注册**：新服务打包进 classpath/进程组即自动登记，网关自动路由，无需改网关配置
   （工程备忘 1：路由漏配三次被冒烟捕获，必须机制性消灭）；
2. **停用即摘除**：管理端停用模块 → 网关路由摘除 + 前端菜单隐藏 + 依赖方明确报缺，其余模块不受影响；
3. **内核/业务边界的运行时表达**：KERNEL 级不可停用，BUSINESS 级可启停，依赖缺失标记 BROKEN
   ——架构文档 3.3 的三层划分从文档落进注册表；
4. **与动态对象同一模型**：F2 动态对象发布 = 向注册表贡献 EXTENSION 级路由与菜单，
   自定义对象与原生服务在注册/路由/菜单三层完全同构。

## 2. 现状差距

| # | 现状 | 问题 |
|---|------|------|
| 1 | 网关路由硬编码 `application.yml` | 新增 API 前缀必须同步改配置，漏配只能靠冒烟发现 |
| 2 | Flyway 各服务独立历史表（共享库） | "不装不迁移"天然满足，但**模块与迁移的对应关系无登记**，管理端不可见 |
| 3 | 前端菜单/路由硬编码 | 模块停用后前端仍显示入口，点击 404 |
| 4 | `dev-up.sh` 启动清单硬编码 | 与服务清单手工同步 |
| 5 | 权限点/编号规则种子随 auth 迁移播种 | 模块与权限点的归属关系松散，停用模块权限点仍残留生效 |
| 6 | 服务间调用 URL 环境变量直连 | 模块缺失时调用方只得到运行时连接错误，无"依赖未启用"语义 |

## 3. 核心设计

### 3.1 模块自描述（Module Descriptor）

每个模块在 classpath 根提供 `openforge-module.yml`，约定优于配置：

```yaml
moduleKey: material                      # 唯一键（= 路由 id、注册表主键）
moduleType: BUSINESS                     # KERNEL / BUSINESS / EXTENSION / AI
displayName: 物料与 BOM
version: 0.1.0
routes:                                  # 声明的 API 前缀（网关路由据此生成）
  - /api/v1/parts/**
  - /api/v1/part-categories/**
  - /api/v1/boms/**
dependencies: []                         # 依赖的 moduleKey（auth 取号、权限查询等隐式依赖除外）
menu:                                    # 前端菜单贡献（动态对象发布时同结构生成）
  - { path: /material, title: 物料, icon: Package }
flyway:
  historyTable: flyway_material_history  # 不装不迁移的登记面
health: /actuator/health
```

类型分级（对应架构文档 3.3 三层）：

| 类型 | 模块 | 停用策略 |
|------|------|----------|
| KERNEL | gateway、auth、common/security、metadata | **禁止停用**（注册表校验拒绝） |
| BUSINESS | material、doc、workflow、change、knowledge、project | 可启停，停用需无他人依赖 |
| AI | ai-gateway（Python，非 JVM classpath） | 可启停；声明式注册（见 3.2） |
| EXTENSION | 动态对象（每个已发布 meta_object 一个） | 随对象生命周期，发布注册/删除注销 |

### 3.2 注册中心（sys_module 表 + 自注册）

Nacos 引入前用共享库表作注册表（演进见 §7，注册 API 形态不变）：

```sql
CREATE TABLE sys_module (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    module_key    VARCHAR(64)  NOT NULL,
    module_type   VARCHAR(20)  NOT NULL,      -- KERNEL/BUSINESS/AI/EXTENSION
    display_name  VARCHAR(128) NOT NULL,
    version       VARCHAR(32)  NOT NULL,
    status        VARCHAR(20)  NOT NULL DEFAULT 'ENABLED',  -- ENABLED/DISABLED/BROKEN
    routes        TEXT         NOT NULL,      -- JSON 数组
    menu          TEXT,                       -- JSON 数组（可空）
    dependencies  TEXT         NOT NULL DEFAULT '[]',
    flyway_table  VARCHAR(64),
    health_path   VARCHAR(128),
    owner_ref     BIGINT,                     -- EXTENSION 型指向 meta_object.id
    registered_at TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    heartbeat_at  TIMESTAMP,                  -- 周期上报（默认 60s，超时 3 倍标记 BROKEN）
    CONSTRAINT uk_sys_module_key UNIQUE (module_key)
);
```

**注册协议**：

1. **JVM 模块**：`openforge-common` 提供 `ModuleAutoConfiguration`——启动时扫描 classpath 的
   `openforge-module.yml`，调 auth `POST /api/v1/internal/modules`（X-Internal-Token）幂等 upsert
   （key 冲突时 version/routes 以运行实例为准，status 尊重管理端设置）；
2. **Python AI 网关**：启动时同接口声明式注册（HTTP POST，与 JVM 同协议）；
3. **动态对象**：发布流水线（F2-3）追加一步——注册
   `moduleKey=dyn:{objectKey}, type=EXTENSION, routes=[/api/v1/objects/{objectKey}/**], menu=[...],
   owner_ref=meta_object.id`；对象表预留删除语义时同步注销；
4. **心跳**：注册器每 60s 上报 `heartbeat_at`；网关路由生成时过滤
   `status=ENABLED AND (heartbeat 未超时 OR module_type=EXTENSION)`——EXTENSION 无进程，不参与心跳。

### 3.3 网关动态路由 + 启动自检

- 路由来源从静态 yml 切换为：**sys_module 表（主） + application.yml 兜底（内核路由）**；
- 刷新机制（渐进）：
  - 阶段一（本期）：定时轮询 30s + `POST /actuator/gateway/refresh-modules` 手动刷新；
  - 阶段二（Nacos 到位）：注册/停用事件推送，轮询降级为兜底；
- **启动自检**（工程备忘 1 的机制化）：网关启动与每次刷新时执行
  `已注册模块声明的 routes` vs `实际生效路由` 比对，缺失则：
  ERROR 日志逐条列出（`route-missing: /api/v1/docs/** (module=doc)`）+
  health 上报 `DEGRADED`（details.modules.missing）——冒烟能一眼看见，不再依赖人点出来；
  BROKEN 模块同样不再静默摘除：自检结果 `brokenModules` 携带原因
  （`change (依赖未启用: workflow)`）进入 `GET /actuator/module-routes` 与
  health details，网关侧 WARN `module-broken: ...`；
- 停用模块的路由直接摘除（未注册前缀落 404，响应体携带
  `"module disabled: doc"` 语义，而非裸 404）。

### 3.4 依赖守护与停用语义

1. **注册时校验**：`dependencies` 引用的模块不存在或 DISABLED → 本模块标记 BROKEN，
   ERROR 日志 `module broken: change, missing dependency: workflow`；BROKEN 模块路由摘除；
   依赖恢复自动回归 ENABLED 时 INFO 日志 `module recovered: ...`；
2. **停用时反查**：停用模块前反查依赖方，存在 ENABLED 依赖方 → 拒绝
   （错误码 4020 MODULE_HAS_DEPENDENTS，语义对齐 ORG_HAS_CHILDREN 的既有惯例）；
   KERNEL 模块停用请求直接拒绝（4021 MODULE_KERNEL_IMMUTABLE）；
3. **依赖方报缺**：服务间调用统一走 `ModuleRegistryClient.ensureAvailable(moduleKey)`
   前置检查（openforge-security 同包提供，权限查询/取号调用点接入），
   依赖缺失抛 `MODULE_DISABLED`（4022）而非连接超时——前端可提示"请联系管理员启用 xx 模块"。

### 3.5 前端与脚本

- 新增 `GET /api/v1/modules`（登录即可）：返回 `status=ENABLED` 模块的菜单贡献
  （BUSINESS/EXTENSION 合并排序）→ 前端导航由静态清单改为注册表驱动渲染；
- `GET /api/v1/modules/admin`（`module:manage` 权限）：全量模块 + 状态/版本/心跳/迁移表，
  管理页提供启停操作（对应 `POST /api/v1/modules/{key}/disable|enable`）；
- `dev-up.sh` 启动清单参数化：`SERVICES="auth gateway material ..."` 环境变量覆盖默认全集，
  与注册表模型对齐（不启动的服务自然不注册、不迁移、不路由）。

### 3.6 新错误码与权限

| 码 | 含义 |
|----|------|
| 3013 MODULE_ALREADY_EXISTS | 模块键冲突（同 key 不同实现的注册冲突） |
| 4020 MODULE_HAS_DEPENDENTS | 存在启用中的依赖方，禁止停用 |
| 4021 MODULE_KERNEL_IMMUTABLE | 内核模块禁止停用 |
| 4022 MODULE_DISABLED | 依赖模块未启用 |
| 4023 MODULE_NOT_FOUND | 模块不存在 |

权限点：`module:manage`（auth V18 播种 + ADMIN 绑定，随 A4-1 迁移）。

## 4. 安全红线

1. 注册/心跳/启停内部端点强制 X-Internal-Token（与 auth 既有内部接口同防线），不经网关路由；
   `module:manage` 为唯一管理权限，启停操作写审计日志（操作者/模块/前后状态）；
2. routes 字段仅接受 `^/api/v1/[a-z0-9_/-]+$` 白名单形态，且**不得与 KERNEL 模块既有前缀重叠**
   （防止恶意/误注册的模块劫持 `/api/v1/auth/**`）；重叠注册拒绝（3013）；
3. EXTENSION 型注册仅允许发布流水线内部调用（owner_ref 必填且须为已发布对象），
   外部不可直接注册 EXTENSION；
4. 网关兜底路由（yml）只保留 KERNEL 前缀，业务前缀一律走注册表——保证"停用即摘除"无死角。

## 6. 验收标准（A4 Definition of Done）

1. 新增一个业务服务（或临时 mock 模块）：不改网关任何配置，注册后 30s 内自动路由生效；
2. 停用 doc：`/api/v1/docs/**` 返回 `module disabled` 语义、前端菜单隐藏、material 等其余模块功能不受影响；重新启用后全部恢复；
3. 网关故意漏配/摘除一条路由 → 启动自检 ERROR 列出缺失前缀，health DEGRADED；
4. 停用 workflow 后停用 change 被拒绝（4020）；停用 auth 被拒绝（4021）；
5. 动态对象发布后出现在前端导航（A4-4）；
6. Testcontainers：注册→路由→停用→恢复全链路真实 PG 绿。
